# Power BI Project Structure

Power BI files can be stored in different formats. The most familiar format is `.pbix`, but for GitHub usage the better direction is usually `.pbip`.

## PBIX

`.pbix` is a packaged Power BI report file. It is easy to open and share, but it is not friendly for Git review because most of the content is stored as a binary package.

Use `.pbix` when:

- You need to send a finished report to someone.
- You want a single portable file.
- You are not reviewing changes through Git.

## PBIP

`.pbip` is a Power BI Project file. It points to report and semantic model folders.

Typical structure:

~~~text
SalesDashboard/
  SalesDashboard.pbip
  SalesDashboard.Report/
  SalesDashboard.SemanticModel/
~~~

This is useful because report and model metadata are separated into project files. That makes the project easier to document, review, and version.

## Practical Rule

For learning and portfolio work:

- Keep documentation in Markdown.
- Keep datasets small and clean.
- Use PBIP when Power BI Desktop is available.
- Export screenshots for GitHub previews when needed.
- Keep `.pbix` exports as release artifacts, not as the only source.

## Important Warning

Not every Power BI project file should be manually edited. Some files are generated by Power BI Desktop and should be changed only through Power BI unless the schema is documented and the change is intentional.
